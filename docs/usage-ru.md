# Сборка и управление

[README](../README.ru.md) · [English manual](usage.md)

## Требования и сборка

Linux или macOS, Python 3.10+, компиляторы C11/C++17, pkg-config и файлы разработки SDL2. SDL2_ttf и внешние шрифты не нужны. Нужен собственный исходный ROM USA размером 1 МиБ без перестановки байтов; точный хеш — в [профиле](../profiles/dune-us.json). Windows-упаковка отдельного сборщика пока не реализована.

Ubuntu / Debian:

```sh
sudo apt install git python3 build-essential pkg-config libsdl2-dev
```

Arch Linux:

```sh
sudo pacman -S --needed git python base-devel pkgconf sdl2
```

```sh
git clone https://github.com/kruzeman/ReArrakis.git
cd ReArrakis
python3 tools/build_dune.py '/путь/к/Dune - The Battle for Arrakis (U) [!].gen'
./run-dune.sh
```

Путь с пробелами заключай в кавычки. Сборщик проверяет хеш до извлечения данных и не скачивает ROM. Звук, мышь, адаптивная карта и зум включаются автоматически.

В игнорируемой папке `build/` появляются `dune` — игра, `dune.c` — перевод в C, `dune.json` — отчёт анализа, `dune-z80*.bin` — шаблоны звукового драйвера. Данные ROM встроены в игру.

После обновления исходников пересобирай игру. Используй именно `tools/build_dune.py`: он передаёт общему рекомпилятору игровые точки входа и варианты Z80-драйвера.

Для генерации C без компиляции:

```sh
python3 tools/build_dune.py '/путь/к/Dune.gen' --emit-only
```

## macOS

Если Clang недоступен, установи Command Line Tools. Недостающие Python/SDL2
можно установить через Homebrew:

```sh
xcode-select --install
brew install python pkgconf sdl2-compat
```

Уже установленная SDL2 также подходит. Обычный сборщик создаёт нативную
программу для текущего Mac; отдельный компилятор и Python-пакеты не нужны.
Из папки проекта:

```sh
python3 tools/build_dune.py '/путь/к/Dune - The Battle for Arrakis (U) [!].gen'
./run-dune.command
```

После сборки открой **run-dune.command** двойным щелчком в Finder. Он вызывает
обычный лаунчер и передаёт аргументы, включая `--audio mute`.
Звук, мышь, адаптивная карта и зум используют тот же код, что и в Linux.
Если F11 назначена системному действию, используй **Fn + F11**.

### Приложение без окна Терминала

После обычной SDL-сборки:

```sh
python3 tools/build_macos_app.py
open build/ReArrakis.app
```

Открывай `ReArrakis.app` двойным щелчком; окно Терминала не появляется.
Приложение можно перенести в другую папку на этом Mac. Внутри находится
исполняемый файл с твоим ROM, а SDL используется из установленной системы.
Это локальная сборка, не универсальный пакет для распространения.
Не публикуй приложение или игровые данные.

Рабочие файлы и журнал `launch.log` сохраняются в
`~/Library/Application Support/ReArrakis/`. При ошибке запуска проверь журнал.
Подпись локальная ad-hoc, без нотариализации. Перед повторной упаковкой
перемести старое приложение либо задай новый путь через
`--output '/путь/ReArrakis.app'`. Аргумент `--binary '/путь/dune'`
позволяет упаковать другой готовый нативный SDL-бинарник.

## Управление

| Ввод | Действие |
| --- | --- |
| Левая кнопка мыши | Выбор / подтверждение / размещение здания |
| Правая кнопка | Приказ выбранному юниту; иначе B |
| Средняя кнопка | B / отмена |
| Указатель у края окна | Прокрутка; отведи внутрь, чтобы остановить |
| Левая кнопка на миникарте | Перенести центр расширенного обзора |
| Колесо | Зум 50–100%, шаг 10% |
| 0 | Вернуть 100% |
| F11 | Полный экран |
| F3 | Примерная занятость оригинального 68000 |
| Стрелки | Крестовина |
| Z / X / C | A / B / C |
| Enter | Start |
| Пробел | Пауза рантайма |
| Tab удерживать | Ускорение |
| Esc / F10 | Меню паузы |
| F1 | Настройки контроллера |

Мышь работает и в поддержанных игровых меню. Цены, приказы, строительство и перемещение обрабатывает исходный код игры.

Карта подстраивается под окно, интерфейс рисуется отдельно. Заставки и меню сохраняют исходные пропорции. Размер расширенной сцены ограничен 1024 × 768 исходными пикселями: необычные пропорции окна могут ограничить фактическое уменьшение. Навигация по миникарте добавлена недавно и ещё требует ручной проверки в игре.

## Звук

При сборке включается ymfm; скрипт запуска использует `--audio on`.

```sh
DUNE_VOLUME=50 ./run-dune.sh
./run-dune.sh --audio mute
./build/dune --headless --audio on --limit 2000000 --dump-audio build/dune.wav
```

`DUNE_VOLUME` принимает 0–200, по умолчанию 100. Значение 50 уменьшает текущую громкость вдвое, 0 выключает звук. По умолчанию исходный сигнал усиливается в 4 раза с ограничением пиков. Раздельная балансировка музыки, эффектов и голосов пока не реализована.

`mute` оставляет Z80 работающим без синтеза. `stub` отключает Z80 и нужен для диагностики, а не обычной игры.

## Проверки и диагностика

```sh
make test
make demo
./build/dune --headless --audio mute --limit 2000000 --dump-frame build/frame.ppm
```

Тестам и демо ROM не нужен. Проверки SDL пропускаются, если нет файлов разработки SDL2. После генерации `build/dune.c` можно запустить проверку на игровом коде:

```sh
cc -std=c11 -O0 tools/smoke_dune.c -o build/smoke-dune
./build/smoke-dune 7200 mute
```

Остальные игровые проверки в `tools/` описаны в [журнале разработки](dune-status.md). Успешная проверка не означает, что проверена вся кампания.

`status=budget` означает достижение заданного лимита инструкций. При ошибке пришли полную строку `execution stopped at ...` / `fault at ...`, хеш ROM, дом, миссию и действие перед остановкой.

Если не найден SDL2, нужен пакет разработки. Если звук «не скомпилирован», пересобери через `tools/build_dune.py`. Для клонирования приватной репы нужен доступ GitHub.

Не коммить и не прикладывай ROM, ресурсы, сгенерированный игровой код, исполняемые файлы и сохранения.

## Индикатор занятости 68000

F3 включает панель `68K: …%` сверху слева. Это доля тактов виртуального 68000
вне штатного цикла ожидания VBlank ($0FDA/$0FDE), усреднённая за 15 кадров.
Обработка прерываний считается работой, остановленный CPU — ожиданием.
Оценка приблизительная: другие циклы ожидания тоже считаются работой.
Это не загрузка процессора компьютера, GPU или счётчик FPS. Частота консоли,
бюджет инструкций и скорость игры не меняются. По умолчанию панель выключена.

В отладочной панели F3 строка `SPD: …%` сравнивает виртуальное время консоли
с реальным за интервал от полсекунды. Около 100% — нормальная скорость,
50% — половина скорости. Это не частота обновления игровой логики:
её оригинальные замедления возможны и при 100%. На паузе показывается `--%`.

Эксперимент в debug: запуск с двойной частотой 68000, F4 переключает 1x/2x.
F3 показывает множитель (68K: 1/2). На каждый цикл CPU приходится вдвое
меньше времени периферии; VDP, Z80 и звук сохраняют штатную частоту.
Это может менять игровую логику, зависящую от CPU. SPD показывает скорость
консоли относительно реального времени, а не множитель CPU.

Мышь добавлена в оригинальные настройки и экран пароля: наведение выбирает
строку/клавишу, левый клик активирует. Для значений левая половина строки
переключает назад, правая — вперёд. В клавиатуре доступны буквы, `<`/`>`
и `!` с оригинальным действием. Правый клик закрывает настройки/пароль;
в подтверждении левый клик отвечает «да», правый — «нет». Изменения
выполняют оригинальные обработчики, без прямой записи значений настроек.

## Геймпад и настройки

**F1** открывает настройки; **Esc / F10** — главное меню паузы с пунктом Controller settings. Для F-клавиш
на Mac может понадобиться Fn. Esc возвращает назад, выход из игры — **Quit game**.
Неназначенная кнопка Back/Select тоже открывает настройки.

- **Pad** выбирает один контроллер по имени и номеру. Остальные не влияют на
  игру. При отключении выбранного пада управление останавливается; другой
  выбирается вручную. Лимита в два устройства нет.
- **Input** выключает ввод геймпада. **Mouse** отдельно выключает игровую мышь
  и прокрутку у края; в настройках мышь и клавиатура продолжают работать.
- **Cursor** — левый/правый стик или выключено. **Digital** — отдельный режим
  стика как крестовины, по умолчанию выключен. Одни оси не используются
  одновременно для плавного курсора и цифровых направлений.
- **Buttons / D-pad** — ручное назначение A/B/C/Start и всех четырёх направлений.
  Выбери строку, нажми Enter/щёлкни мышью и нажми нужную кнопку, крестовину,
  триггер или направление оси. **Assign all eight** назначает всё по очереди.
  Между нажатиями отпускай контролы. Esc отменяет, Delete/Backspace очищает.
  При одиночном назначении уже занятой кнопки два назначения меняются местами.
- **Axes / Deadzone** — оси X/Y, инверсия, мёртвая зона 5–60%, скорость 25–300%.
  Отпусти стики и триггеры, затем щёлкни **Calibrate**: текущие значения станут
  центрами. **RAW / CENTER** показывают реальные значения и сохранённый центр.
  Сброс возвращает центры 0, мёртвую зону 30%, скорость 100%.

После выбора пада стик должен вернуться в откалиброванный центр. Настройки
не управляются аналоговыми стиками, поэтому дрейф не мешает их исправить.
Крестовина, кнопки, стрелки клавиатуры, Enter и мышь работают в меню независимо
от игровых назначений. Системная кнопка Guide может также вызывать функции macOS.

Профили сохраняются автоматически: `gamepad.cfg` — выбор устройства,
`gamepad-<SDL GUID>.cfg` — настройки модели. Для `.app` папка:
`~/Library/Application Support/ReArrakis/`; для консольного запуска — рабочая.
Одинаковые модели с одним GUID делят профиль; во время игры выбран конкретный
экземпляр по instance ID. Старые файлы читаются и обновляются при сохранении.
Для нераспознанных SDL устройств можно положить `gamecontrollerdb.txt` рядом.


### Меню паузы и сохранение состояния

**Esc / F10** → **Resume game**, **State slot**, **Save state**, **Load state**,
настройки контроллера, полный экран, громкость, скорость CPU и выход.
Стрелки/крестовина выбирают строку, Enter/A подтверждает, Esc/B возвращает
на уровень назад. Все строки доступны мышью. Влево/вправо меняет слот,
громкость или скорость; опасные действия стрелками не подтверждаются.

Есть **10 слотов** со статусом и датой сохранения. Перезапись, загрузка и выход
требуют подтверждения; сначала выделена **Cancel**. После загрузки игра остаётся
на паузе — нажми Resume game. Пустой или повреждённый слот текущую игру не меняет.

В `.app` файлы `state-01.grs` … `state-10.grs` лежат в
`~/Library/Application Support/ReArrakis/`; при запуске бинарника — в рабочем
каталоге. Они переживают перезапуск приложения и содержат состояние процессоров,
памяти, видео и звуковых чипов. Это локальные снимки конкретного runtime/ABI:
другая сборка с изменённым runtime может их не прочитать. Сохрани старую `.app`,
если нужны её состояния. Во время записи WAV save/load недоступны.
Громкость, полный экран и выбранный слот действуют в текущем сеансе.
